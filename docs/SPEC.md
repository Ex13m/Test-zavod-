# 📋 Спецификация: «Контент-Завод» (lure-content-factory)

> Методика: **spec-pilot** (интервью → спека → сборка → проверка).
> Статус: реализовано в v0.1.0, спека зафиксирована как источник правды.
> Владелец продукта: ex13m. Разработка и документация: Claude Code.

---

## 1. Цель продукта

Дашборд-«завод» для производства **продающих постов-воронок** под рыболовные приманки:
пользователь загружает фото приманки → завод эвристически собирает пост
(крючок внимания → выгоды → доказательство → CTA со ссылкой на сайт) →
пост хранится в истории и рассылается по каналам дистрибуции.

**Ключевая метрика ценности:** время от «фото приманки» до «пост в Telegram-канале» < 60 секунд.

## 3. Стек и архитектура

- **Vite 5 + React 18** — SPA без бэкенда, статический билд → идеально под Netlify.
- **Zustand + persist** — состояние с автосохранением в localStorage.
- **idb-keyval (IndexedDB)** — хранение изображений (dataURL), в сторе — только ключи.
- **Netlify Functions** — единственный серверный компонент: прокси к Telegram Bot API
  (`api.telegram.org` не отдаёт CORS, из браузера напрямую нельзя).
- **Canvas 2D** — процедурная анимация: рыба на «позвоночнике» из 22 сегментов
  (inverse kinematics) преследует блуждающую приманку; пузырьки, планктон, лучи света.
- Дизайн-система «Глубина»: тёмная подводная тема, glassmorphism, шрифты Unbounded/Manrope,
  учёт `prefers-reduced-motion`.

### Альтернативы, рассмотренные и отклонённые (анализ трендов 2026)

| Вариант | Почему нет (сейчас) |
|---|---|
| Next.js / SSR | Бэкенд не нужен, статический SPA дешевле и проще деплоится на Netlify |
| Svelte 5 / Astro | Экосистема React шире; Astro — для контент-сайтов, не для интерактивного дашборда |
| Tailwind | Кастомная дизайн-система на CSS-переменных даёт нетривиальный вид без утилитарного шума |
| LLM-генерация текста через API | Требует ключей и бюджета; v1 — эвристический шаблонизатор, LLM — в дорожной карте (v2) |
| Прямой вызов Telegram из браузера | Невозможно: CORS. Решение — serverless-прокси Netlify |

## 4. Функциональные требования (реализация v0.1.0)

### 4.1 Склад приманок
- Drag&drop / выбор нескольких фото (JPG/PNG/WEBP), сжатие до 1200px.
- Автоопределение типа приманки по имени файла (8 типов: воблер, вертушка, колебалка,
  силикон, джиг-головка, поппер, балансир, спиннербейт) + ручная правка на карточке.
- Удаление с очисткой IndexedDB.

### 4.2 Конвейер генерации
- Рецептура: приманка × формула воронки (**AIDA, PAS, Сторителлинг, Экспертный разбор, FOMO**)
  × тон (дружеский / экспертный / дерзкий / премиум) × длина (короткий / средний / длинный).
- База знаний по каждому типу: целевая рыба, сезоны, выгоды, боли, соцдоказательства, лексика.
- Детерминированный PRNG (mulberry32) — «Пересобрать» даёт новый вариант по новому seed.
- CTA-ссылка на сайт из настроек + автоматическая UTM-разметка
  (source настраиваемый, medium=social, campaign=формула). Кириллические домены не punycode-ятся.
- Анимация линии сборки (6 стадий) + печатающийся текст результата.

### 4.3 Копирование стиля повествования
- Загрузка скринов эталонных постов.
- Эвристический анализ v1 по пиксельным признакам (яркость, насыщенность, плотность
  контрастных зон ≈ плотность текста) → профиль: плотность эмодзи, рубленость фраз,
  длина, формальность, хэштеги.
- Профиль автоматически применяется ко всем новым постам. Точка расширения — OCR+LLM (v2).

### 4.4 История и хранение
- Все посты — на «складе готовой продукции»: фильтры по формуле, раскрытие полного текста,
  копирование, удаление, экспорт JSON, отметки «куда опубликован».
- Персистентность: localStorage (тексты/настройки) + IndexedDB (картинки). Копия фото
  приманки прикрепляется к посту — пост живёт независимо от приманки.

### 4.5 Дистрибуция (настраиваемый выход)
- **Telegram (реальный):** токен бота + ID канала задаются в дашборде, отправка через
  Netlify Function `telegram-post` (sendPhoto с caption ≤1024, длинный текст — догоняющим
  sendMessage). Токен хранится только в браузере пользователя.
- **Автопостинг (реальный):** универсальный вебхук с пресетами **n8n / Make / Zapier / Albato**;
  payload: `{source, version, title, text, meta, photoDataUrl?, createdAt}`;
  фолбэк `no-cors` для вебхуков без CORS-ответа.
- **ВК, Дзен, Instagram, ОК** — заглушки с тумблерами (пост помечается «в очередь»).
- Журнал отправки в реальном времени.

### 4.6 Настройки завода
- Бренд, URL сайта, UTM вкл/выкл + utm_source, рецептура по умолчанию, полный сброс.

## 5. Нефункциональные требования

- Полностью на русском языке.
- Без обязательных внешних сервисов: всё работает локально, деплой — статический.
- Анимации отключаются при `prefers-reduced-motion`.
- Билд < 250 КБ JS (факт: ~202 КБ, gzip 69 КБ).

## 6. Критерии готовности (verify before build)

- [x] `npm run build` без ошибок.
- [x] E2E-прогон в браузере (Playwright): загрузка приманки → генерация → сохранение →
      экран дистрибуции; ноль ошибок JS в консоли.
- [x] Скриншоты всех ключевых экранов сняты и проверены визуально.
- [x] Грамматика шаблонов: согласование рода типа приманки (этот/эта, м/ж).
- [ ] Публикация в реальный Telegram-канал — проверяет пользователь после своего деплоя
      (зона человека).

## 7. Ограничения и допущения

- Генерация v1 — шаблонная эвристика, без LLM: тексты вариативны, но конечны.
- «Поиск брендовых постов по фото в интернете» в v1 замещён загрузкой скринов-эталонов
  пользователем (юридически и технически чище); автопоиск — кандидат в v3.
- Один пользователь = один браузер (нет аккаунтов/синхронизации).
